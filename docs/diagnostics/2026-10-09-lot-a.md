# Diagnostic préalable — achèvement du lot A

Branche exclusive : feature/gpt6-evolution-smsi-grc. Périmètre : instructions A1–A6, après validation de A1a, A1b1 et A3–A6.

A1 dispose d'une file de sauvegardes, d'un exécutant hôte, d'archives chiffrées et d'une restauration serveur validée. Il manque le catalogue des archives externes à la file, la configuration de rétention/planification, la vérification demandée depuis le navigateur et la restauration guidée. Une restauration remplace sa propre base de suivi : son journal doit survivre hors de PostgreSQL. Les anciennes demandes contenues dans une archive ne doivent jamais être exécutées après restauration.

A2 : Caddy termine TLS (docker/Caddyfile, service web). Son API d'administration est désactivée ; les clés restent hors de l'API. CADDY_TLS dans .env fournit actuellement le mode interne, ACME ou un couple de fichiers externes. Aucun upload, exécutant de certificats ni retour arrière web n'existe. Les montages et le démarrage du frontal doivent pouvoir choisir un couple web validé sans modifier .env. Une terminaison externe doit rester en observation seule.

A3–A6 sont déjà implémentés, avec tests de déconnexion/multi-onglets, guide filtré par droits et inspecteur rétractable. Ils doivent être rejoués ; aucun style ni jeton ne doit changer. Le guide doit décrire uniquement les capacités réellement disponibles, y compris les conditions d'activation du nouvel exécutant.

Choix : étendre le protocole hôte avec des commandes fixes et une file transactionnelle partageant le verrou de sauvegarde. Aucune commande shell, clé de sauvegarde ou destination arbitraire n'est acceptée par HTTP. Planification hebdomadaire à heure UTC explicite, rétention bornée ; archives identifiées par nom/empreinte, contrôlées à nouveau au moment de l'utilisation. La restauration exige une vérification préalable, une confirmation, une sauvegarde de sécurité vérifiée et un retour arrière contrôlé. Les interruptions ne relancent pas l'opération demandée. Un retour arrière interrompu bloque l'exécutant et exige une reprise exploitant.

Les demandes TLS chiffrent la clé en base avec Vault et effacent ce contenu à la fin. L'exécutant écrit les fichiers privés, valide Caddy, vérifie le certificat effectivement servi et la santé, puis restaure l'ancien couple en cas d'échec. La gestion web est désactivée par défaut ; une déclaration de terminaison externe interdit toute modification. Les certificats internes/ACME continuent d'être renouvelés par Caddy, sans prétendre offrir un renouvellement manuel non supporté.

Validation attendue : contrats stricts, droits/CSRF/version/concurrence/audit/idempotence, reprise hors base, arrêt/échecs/rollback, certificats incohérents/expirés/mauvais hôte, absence de secrets dans réponses/journaux, ordonnanceur sans doublons, sauvegardes historiques compatibles ; recette réelle isolée, tous les contrôles CI et comparaisons visuelles. Aucune intervention de production et aucune fusion.

## Réalisation et vérifications

La migration additive 007, le protocole hôte et les écrans d'administration réalisent les fonctions manquantes de A1/A2. Les migrations antérieures, les jetons graphiques, les références visuelles et les modules hérités sont conservés. La planification et la gestion TLS web restent désactivées par défaut ; l'exploitation exige l'installation explicite de l'exécutant décrite dans le guide.

Les contrôles locaux de compilation, types, lint, format et ShellCheck passent. La suite API compte 159 tests réussis ; les 14 scénarios de l'exécutant couvrent notamment les interruptions, les retours arrière, les verrous communs, le créneau UTC, les fichiers spéciaux et l'espace disque insuffisant. Les cinq nouveaux scénarios navigateur passent sur la pile isolée, sans renouvellement des captures. Le CSS compilé conserve l'empreinte index-BVNHOy3h.css.

La CI complète ajoute une recette isolée de sauvegarde, vérification, restauration, échec avec retour arrière, planification sans doublon, remplacement TLS, retour arrière TLS et retour à .env. Ses résultats définitifs et ceux de la non-régression complète seront consignés dans la [PR de travail #12](https://github.com/yousername-ha/suivi-audits/pull/12). Ces essais ne constituent pas un déploiement ni une intervention sur les données de production.
