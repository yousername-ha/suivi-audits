# Diagnostic préalable — B2, configuration de l’environnement

Branche exclusive : `feature/gpt6-evolution-smsi-grc`. Diagnostic établi avant modification fonctionnelle.

Les huit sections de Paramètres utilisent zod, des ETag et des permissions serveur. Elles couvrent identité, cycle, référentiels, apparence, notifications, imports, sauvegardes et sécurité. Les notifications PostgreSQL/SSE permettent de renouveler les caches. Les rôles et la garde commune de B1 sont réutilisables. Le journal d’audit est immuable ; une nouvelle configuration doit être enregistrée avec son audit dans la même transaction.

Les valeurs métier v2 restent dans `app_state` et les constantes du HTML historique. L’IA utilise impact maximum × probabilité, un facteur DSCP, une réduction par maturité et une pondération de l’effort ; les incidents utilisent une autre matrice impact × urgence. Ces méthodes ne sont pas interchangeables. Modifier une constante globale recalculerait le passé et casserait les exports historiques. Aucun de ces calculs ne doit être remplacé silencieusement par une matrice générique.

## Première livraison B2 : échelles et matrices versionnées

Ajouter Administration → Configuration de l’environnement : édition structurée des échelles d’impact, probabilité et maturité, des seuils de criticité et d’une règle fermée (produit, somme ou matrice explicite). Un simulateur explique les résultats. Validation des identifiants, ordre, bornes, couverture et unicité des cellules ; aucun code ou formule libre. Prévisualisation sans écriture, confirmation liée à la version et à l’empreinte, motif obligatoire, concurrence optimiste, audit transactionnel.

Chaque publication crée une version immuable. Le retour à une ancienne définition est une nouvelle publication ; il ne modifie jamais une version existante. Une simulation mentionne sa version, sans être enregistrée comme évaluation métier. La configuration initiale est une proposition organisationnelle (produit 1–5, seuils 5/10/16), sans valeur normative et sans application aux enregistrements v2. Les labels de maturité reprennent le vocabulaire IA existant, mais la méthode générique reste distincte.

Le raccordement des évaluations métier avec référence explicite de version, les nomenclatures/actions/preuves/contrôles, workflows, modèles et tableaux de bord constituent les sous-lots suivants de B2. Cette première livraison ne prétend pas terminer B2 et ne rend pas l’outil historique dépendant de nouvelles règles.

## Validation attendue

Non-régression des suites existantes, PR de branche sans fusion de main.

## Résultat local de B2a

Édition, publication, consultation des anciennes définitions et simulation livrées. Les publications distantes invalident la lecture via SSE et conservent le brouillon. Remplacer un brouillon par une ancienne définition ou recharger la version courante exige confirmation. L’accès est proposé depuis Administration → Système, en conservant les onglets et les captures des pages existantes.

Validation locale : 209 tests partagés, 191 tests API PostgreSQL, 102 tests UI et 16 tests web passent (518 tests Vitest). Les trois scénarios navigateur vérifient publication réelle d’une matrice à 390 px, ancienne version intacte, reprise préparée sans publication, changement distant/brouillon préservé/rechargement confirmé, refus d’une définition incohérente et consultation seule. Les douze captures Paramètres/Administration restent inchangées à 390/768/1440 px, en clair et sombre. Construction, lint, typage, format et syntaxe Python passent. La recette Docker de CI est étendue pour comparer l’intégralité des versions/configuration avant et après mise à jour et retour arrière ; son résultat sera suivi sur GitHub.

B2a ne raccorde pas encore les évaluations métier, workflows, nomenclatures, modèles et tableaux de bord. B2 reste ouvert ; le passage au lot C n’est pas déclaré.
