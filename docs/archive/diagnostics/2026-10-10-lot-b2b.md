# Diagnostic préalable — B2b, évaluations IA versionnées

Branche exclusive : `feature/gpt6-evolution-smsi-grc` ; établi avant modification fonctionnelle.

B2a fournit des configurations immuables, sans consommateur métier. Le registre IA est dans `app_state.ai` ; ses scénarios `evals[]` ont des identifiants. Le calcul `aiEval` utilise l’impact maximal, la probabilité, un facteur DSCP, la maturité et l’effort, et est réexécuté à chaque affichage/export. La matrice générique B2a n’est pas équivalente à cette méthode : appliquer automatiquement la dernière configuration effacerait la distinction entre méthodes et modifierait les résultats.

## Raccordement prévu

Un écran Sauge accessible depuis le guide et le menu utilisateur v2 présente les scénarios existants et leurs réévaluations. Les scénarios restent modifiables uniquement dans l’outil historique ; aucune seconde copie éditable de registre. Chaque réévaluation crée une décision immuable liée à l’identifiant du scénario, avec instantané intégral de la source (champs inconnus conservés), empreinte, configuration publiée explicitement choisie, niveaux retenus, résultat serveur et justification. La consultation distingue la méthode historique courante et les nouvelles évaluations organisationnelles, sans les assimiler à une conformité.

Simulation sans écriture puis confirmation, If-Match de l’historique du scénario et empreinte de source : une mutation concurrente du scénario ou une autre évaluation oblige à revalider. Une publication de configuration ne recalcule jamais une décision ; même une ancienne configuration peut être choisie explicitement. Une répétition identique de demande est idempotente, une demande modifiée ou un autre auteur ne peut réutiliser son identifiant. Audit et décision sont atomiques. Les droits IA, l’activation B1 et les gardes session/MFA/origine/CSRF restent applicables.

Une suppression du scénario ne supprime pas les décisions ; elles sont consultables comme source retirée, sans possibilité de réévaluer une référence inexistante ou ambiguë. Une modification de source est signalée sur les décisions passées. Export JSON avec définitions exactes, sous les droits IA et import/export ; pas de réimport implicite de décisions dans le JSON v2. La sauvegarde PostgreSQL conserve ces données.

## Validation attendue et périmètre

Migration additive 011 et schéma ORM ; calcul historique parité v2, source/champs extra intacts, configuration antérieure et résultats inchangés après nouvelle publication ; permissions et module désactivé ; confirmation, concurrentes, empreintes, demandes répétées, audit atomique et immutabilité ; export/version/source supprimée. Recette navigateur sur sources fictives, mobile, consultation seule et erreurs. Le raccordement des autres familles et nomenclatures/workflows demeure au backlog B2 ; aucune migration complète du module IA n’est revendiquée.
