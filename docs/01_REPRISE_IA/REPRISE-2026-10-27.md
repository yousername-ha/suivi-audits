## 4. Accès aux données (ADR 0062) : état final de la conversion Kysely

Suivi détaillé : [CONVERSION-KYSELY](../03_ARCHITECTURE/CONVERSION-KYSELY.md). Toutes les requêtes de l'API passent par
Kysely, sauf celles laissées **volontairement** en SQL, avec un commentaire dans le code :

- agrégats des tableaux de bord (`tableau-de-bord.ts`, `grc/dashboard.ts`, `grc/cartes.ts`) et registre des risques
  (`grc/registre-risques.ts`) : sous-requêtes corrélées, `FILTER`, chemins jsonb (ADR 0062 § 5) ;
- verrous consultatifs (`pg_advisory_xact_lock`) et `LISTEN/NOTIFY` (`realtime.ts`).

Repères pour le nouveau code :

- `svc.db.k` (ou `this.g.db.k`) : instance Kysely ; dans une transaction, `db.tx(async (c, k) => …)` où `k` utilise la
  même connexion que `c` ; `surConnexion(c)` enveloppe un client existant. Types générés : `src/db/types.generated.ts`
  (`pnpm --filter @suivi/api db:types` après une migration ; la CI échoue en cas d'écart).
- ESLint interdit `sql.raw` et `sql.lit`. Identifiants dynamiques issus d'une liste fermée : `sql.table` / `sql.id`.
- jsonb écrit en `JSON.stringify(...)` ; liste vide jamais passée à `in` (garder le cas vide comme l'ancien `= ANY` ou
  `<> ALL` d'un tableau vide) ; compteurs `numUpdatedRows` / `numDeletedRows` convertis par `Number(...)`.
- Aides partagées : `verrouillerEtat(c)` (`legacy/store.ts`), `horsRegistresMasques(masques)` (`grc/registres.ts`),
  `exploitationOccupee` (`operations.ts`), `motDePasse` (`auth.ts`).
- Méthode de preuve suivie pour chaque lot : tests liés verts avant et après ; tout chemin non couvert reçoit un test
  `*-requetes.test.ts`, vérifié aussi sur l'ancien code (`git stash push <fichier>`) ; suite API complète verte.
