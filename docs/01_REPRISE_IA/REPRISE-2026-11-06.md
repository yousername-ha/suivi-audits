### Lot D, points d'attention pour la reprise

- `scripts/backup.sh` applique à l'archive, avant de la publier, le contrôle de `scripts/verifier-archive-restauration.py`
  (structure, secrets, lien au nom). Il libère les copies intermédiaires avant ce contrôle (dossier temporaire de 256 Mo dans
  le conteneur d'exécution) et refuse un lien ou un fichier spécial dans `caddy/data`.
- `scripts/restore.sh` arrête le frontal pendant une restauration manuelle ; dans le parcours de mise à jour web
  (`SUIVI_MAJ_WEB=1`) il le laisse en service pour la page de maintenance. La restauration lancée par l'exécutant
  d'exploitation (sans cette variable) arrête donc aussi le frontal.
- Après une restauration, la clé publique de secours et l'adresse du site de l'hôte font foi (réalignement unique,
  journalisé, `restauration-realignee.json`).
- Le rejeu du guide sur runner vierge (`scripts/ci/guide-api.mjs`) envoie un code TOTP frais pour chaque restauration.
